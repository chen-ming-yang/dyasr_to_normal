# 构音语音到正常语音

说话人 S06。输入一条构音录音，输出音色仍是 S06、发音换成正常音的波形。数据是已有字级 onset 的 1270 条（train 1012 / dev 128 / test 130）。

当前能出声的做法不是把构音频谱直接回归成正常频谱。那条路听不懂。现在先判断每个字是哪个音节，再从正常发音库里取出那个音节来合成。

## 数据里用到什么

| 材料 | 作用 |
|---|---|
| 构音 wav 和人工字级 onset | 输入，以及训练时切字 |
| Qwen3-TTS 克隆的 S06 正常音 | 音节库里的正常发音，不是转换网络的输入 |
| Qwen3-ForcedAligner 的正常音字边界 | 从正常音上切出每个音节的码和波形 |
| IndexTTS 2 的 Wav2Vec2-BERT 第 17 层、RepCodec、s2mel | 冻结。第 17 层做内容特征，RepCodec 出语义码，s2mel 把码变成 mel |
| BigVGAN（22050 Hz，hop 256，80 维） | 冻结声码器 |

字级 onset 只用来切段和造目标。推理如果没有人工 onset，用已有的 onset 模型补边界，测试集 onset MAE 0.122 秒。文本和汉字不进入最后的合成，合成只看到音节序列（如 `wo3`）。

## 当前链路

```text
构音 wav (16 kHz)
  → 冻结 Wav2Vec2-BERT 第 17 层
  → 按字区间池化
  → 音节分类器，每字 top-10（带声调，约 670 类）
  → 音级 4-gram，beam search 纠错
  → 音节库取出该音节的正常语义码
  → 冻结 s2mel（S06 正常音作音色条件）
  → 冻结 BigVGAN
  → 正常音频
```

对应脚本是 `dsr/infer_lm.py`，试听在 `runs/dsr/compare_lm/`。

1. **切字。** 用 onset 把构音分成字。每个字的区间是从前一个 onset 到下一个 onset，最后一字收到句尾。区间里既有字，也有字后的停顿。
2. **判音。** 冻结的第 17 层在这个区间里池化，分类器给出带声调的音节和分数。分类器是注意力池化加 MLP，624 类。单独用它，开发集 top-1 只有 0.040，记住了训练集，没有泛化。
3. **语言纠错。** 不直接取 top-1。每个字留 top-10，再用 1270 句文本训出的音级 4-gram 做 beam search（宽度 8）。分数是声学 log 概率加 `0.3 ×` 语言模型 log 概率。开发集音节准确率从 0.150 升到 **0.173**。正确音节有 43% 落在声学 top-10 里，所以语言模型还有空间，但 1270 句的 n-gram 太小，被高频音节带着走。
4. **取正常发音。** 音节库按「音节 + 声调」存放正常音，来自训练集配对的克隆正常音。5578 个字样本合成 622 个音节，每个音节中位数 4 条。当前合成取该音节的第一条样本的语义码。
5. **合成。** 这些码按顺序接起来，送给冻结的 s2mel，再经 BigVGAN。音色条件用一条 S06 正常参考音。这条推理不把码铺回构音的时长，输出接近正常语速。

## 另一种出声方式

判音结果相同，波形有两条路，对比在 `dsr/infer_compare_ab.py`，试听在 `runs/dsr/compare_ab/`。

| 路 | 做法 | 听感 |
|---|---|---|
| A 拼接 | 检索到音节后，把该音节的正常波形直接接上 | 每个音是真人正常音，语速变快，边界不连贯 |
| B 合成 | 取出该音节的码序列，按构音时长铺开，再进 s2mel | 音质正常，句子仍和构音一样长，保留拖音和停顿 |

两条路的音质都正常。内容错，是因为检索 top-1 只有 0.116，大约 88% 的音节判成了别的音。判错时输出仍是一个清楚的正常音节，只是字不对。

## 为什么不用更早的做法

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 构音 HuBERT 帧直接回归正常 log-mel，再 BigVGAN | 能出声，糊，听不清 |
| v3 | 逐帧预测 8192 类语义码 | 验证集帧准确率 0.001，只记住了训练集 |
| v4 | 逐帧预测 8 维码向量 | 验证集余弦 0.559，帧对齐太脆 |
| v5 | 每个字预测一个 8 维向量，再量化成一个码交给 s2mel | 验证集余弦 0.829。声码器没有问题，但一个字只有一个码，铺满整段后声音又高又听不懂 |
| v6 | 按字存一段正常码序列，用构音特征检索，再铺到构音时长 | 音质正常。检索 top-1 0.131 |
| v8 / v9 | 把检索换成音节分类器，v9 先裁掉字尾拖音 | 开发集准确率仍是 0.040 |

v6 说明音质问题可以解决：正常发音要保留一个音节内部从声母到韵母的变化，不能一个字只留一个码。v7 把键从「字」改成「音节 + 声调」，检索 top-1 仍是 0.116。类别变少没有帮助，卡在构音特征分不开这些音。

## 现在的上限

音节准确率 **17.3%**（开发集，声学分数加 0.3 的语言模型）。听起来是清楚的正常音，内容大部分是错的。

根子是数据。常用 2500 字对应约 1008 个音节，库里只有 622 个，其中 219 个样本不超过 2 条。第 17 层是在正常语音上预训练的，1012 条单说话人构音不够把退化的发音分开。补数据时优先补容易混的声母：`z/zh`、`c/ch`、`s/sh`、`n/l`。按每个音节补到约 5 条估计，还要大约 3070 个音节样本，约 614 句。

声学 top-10 的覆盖从现在的 43% 提高、n-gram 用更多句子重训之后，同一条链路的纠错才会继续上去。在这之前换合成器解决不了内容错误。

## 代码

实现在 `dsr/`。脚本里的数据、权重和 IndexTTS 路径写的是实验机上的绝对路径，本仓库不包含录音、特征和预训练权重。

| 文件 | 作用 |
|---|---|
| `dsr/infer_lm.py` | 当前推理：top-10、4-gram 纠错、s2mel、BigVGAN |
| `dsr/train_syllable_cls.py` | 音节分类器 |
| `dsr/train_syllable_ngram.py` | 音级 4-gram |
| `dsr/eval_topk.py` | 声学 top-K 覆盖 |
| `dsr/sweep_lm_weight.py` | 语言模型权重扫描 |
| `dsr/build_syllable_lib.py` | 按音节加声调建正常发音库 |
| `dsr/infer_compare_ab.py` | 波形拼接和 s2mel 两条路的对比 |
| `dsr/semantic_frontend.py` | 冻结的第 17 层和 RepCodec |
| `dsr/model.py`、`dsr/train.py` | v1：构音帧回归正常 mel |
| `dsr/train_codes.py`、`dsr/train_vec.py`、`dsr/train_char.py` | v3–v5：语义码和逐字向量 |
| `dsr/infer_s2mel.py` | v5 接 s2mel |
| `dsr/build_syllable_templates.py`、`dsr/infer_syllable_template.py` | v6：字级码序列检索 |

s2mel 依赖本机的 IndexTTS 2 源码。`dsr/stubs/audiotools` 用来绕过它训练时才需要的 DAC 依赖。运行前把 `dsr/stubs` 放进 `PYTHONPATH`。
